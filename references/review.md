# 镜头审片

在检查首版或重试镜头前读取本文件。

## 输入

对每个尝试版本生成一张早段/中段/后段联系表：

```bash
bash <skill-dir>/scripts/extract-review-frames.sh \
  shots/attempts/shot_01_attempt_1.mp4 \
  shots/review/shot_01_attempt_1.jpg
```

联系表用于一次看清主体是否稳定、动作是否发生、结尾是否崩坏。只有时间性问题不明确时才
播放原视频或额外抽帧。

## Vision 问题

把本镜的计划内容一并交给视觉能力：

```text
这三个时刻是否清晰表达了空耳句「{misheard}」的字面意思：
「{visual}」？主体、关键道具和动作是否正确？9:16 构图是否可用？
底部字幕安全区是否足够？是否有明显变形、水印、错误文字或安全问题？
```

## 五分制

| 分数 | 标准 |
|---|---|
| 5 | 不看解释也能立即读出字面梗；主体、动作、构图稳定 |
| 4 | 梗清楚，只有轻微瑕疵，不影响使用 |
| 3 | 大致相关，但关键道具或动作不够明确，需要重试 |
| 2 | 只有主题相近，不能表达空耳字面意思 |
| 1 | 主体/动作错误、严重崩坏或不可用 |

4–5 分通过。1–3 分失败，并把最关键的一个失败原因写入 `reason`。

## 重试上限

- Attempt 1：原始 Prompt。
- Attempt 2：只修补 Attempt 1 的主要失败。
- Attempt 3：只修补 Attempt 2 仍存在的主要失败。
- Attempt 3 后停止生成。选择视觉上最好的一版，状态记为
  `failed_best_selected`，交付时标注“未过审，建议人工重做”。

`record-review.mjs` 会拒绝同一镜头记录第四次尝试。
失败后使用 `set-retry-prompt.mjs` 写入最小修补；不要修改已批准计划。若改变空耳梗或画面
语义，则不属于自动重试，必须重新让用户确认。

## 审片记录

`shots/review.json` 必须保留每次尝试：

- 尝试序号与文件
- 联系表路径
- `pass` 或 `fail`
- 1–5 分
- 简短理由
- 使用的 Prompt
- 任务 ID（如有）
- 最终选中的文件与状态

不要删除失败尝试的记录。用户要求重做某镜时，保留旧记录并开始新的 revision。
