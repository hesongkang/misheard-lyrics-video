### 2. HyperFrames CLI（有坑，重点记录）

**坑 1：`npx --yes hyperframes --version` 首次下载超时。**
- 150s timeout 未完成。包本身仅 ~24MB（`npm view hyperframes` 确认 `dist.unpackedSize = 24412327`），不应这么慢，判断为 npx 解析开销 + postinstall 下载浏览器。

**坑 2：`npm install -g hyperframes` 正常安装也超时。**
- 5 分钟 timeout 仍未完成。根因是 postinstall 下载 Chrome Headless Shell（HyperFrames 渲染靠 `puppeteer-core` 逐帧截图，依赖 Chrome，几百 MB）。

**解法：跳过 postinstall 安装。**

```bash
npm install -g hyperframes --ignore-scripts   # 51s，138 个包，成功
```

**坑 3：`--ignore-scripts` 导致 bin 无执行权限。**

```text
$ hyperframes --version
/bin/bash: line 1: hyperframes: Permission denied   # 退出码 126
```

修复：

```bash
chmod +x /home/hsk/.nvm/versions/node/v24.14.1/bin/hyperframes
# 该路径是符号链接 -> ../lib/node_modules/hyperframes/bin/hyperframes.mjs
```

修复后 `hyperframes --version` 输出 `0.7.83`，`transcribe --help` 含 `word-level timestamps`，均通过。
check-deps 识别为 `OK: HyperFrames 0.7.83 via global command`（优先用全局命令，不再走 npx）。

### 3. ffmpeg / ffprobe（sandbox 误报）

**现象**：初次用 `command -v ffmpeg` 检查时报"未安装"，但 `check-deps.sh` 却报 `OK: ffmpeg found`，两者矛盾。

**核实**：直接 `which ffmpeg` 确认实际存在于 `/usr/bin/ffmpeg`（4.4.2）。初次的"未安装"是 bash 调用落在 sandbox 环境中的误报（sandbox 的 PATH/文件系统可见性与真实环境不同）。

**结论**：ffmpeg/ffprobe 系统已有，无需安装。今后做依赖检查时，对 `/usr/bin` 下的系统命令要以 `check-deps.sh` 或 `which` 为准，单次 `command -v` 在 sandbox 下可能误报。

## 七、注意事项

- **统一 `host=codex`**：Claude Code 无 Cola 内置 `gen_video`，所有视频生成都走 listenhub CLI。
- **listenhub 网络切换**：`api.marswave.ai/openapi` 不可达时 CLI 自动切到 `api.listenhub.app/openapi`（或设 `LISTENHUB_OPENAPI_URL`），切换后需重试一次命令（见 `REQUIREMENTS.md`）。
- **首次真实生成才付费**：`tests/run-all.sh` 用 ffmpeg 合成色块视频不花钱；只有真实歌曲走到 `listenhub openapi video create` 才消耗 credits。
- **两道批准门与宿主无关**：候选门（逐句确认前不生成）与渲染门（最终预览确认前不渲染）由 `assert-generation-ready.mjs` 的内容摘要强制，Claude Code 环境下同样生效。
